## Goal

Confidently design and defend an AI/RAG system in an interview, and showcase a
portfolio that backs it up.

## Estimated Time

1–2 weeks.

## Prerequisites

- The full [RAG project](../05-rag-fundamentals/03-first-project.mdx), [Advanced RAG](../06-advanced-rag/index.mdx), and [Production Patterns](../10-production-patterns/index.mdx).

## What You Will Learn

1. [Architecture Narratives](./01-architecture-narratives.mdx) — a repeatable framework for designing RAG/LLM systems.
2. [Tradeoff Discussions](./02-tradeoff-discussions.mdx) — the decisions interviewers probe (RAG vs fine-tuning, latency, cost, scaling).
3. [Portfolio](./03-portfolio.mdx) — package your project so it demonstrates real skill.

### Full roadmaps

Two longer, staged references for the rounds that go beyond AI systems:

4. [System Design Roadmap](./04-system-design-roadmap.mdx) — networking, web servers and gateways, databases, caching, queues, and scaling patterns.
5. [Python LLD Roadmap](./05-python-lld-roadmap.mdx) — UML, SOLID, design patterns, and the class-modelling questions in low-level design rounds.
6. [AI System Design](./06-ai-system-design.mdx) — designing AI and LLM-backed systems specifically, with the architectures and tradeoffs interviewers probe.

## The Design Framework (used throughout)

For every system, cover: **Requirements → High-level architecture → Data flow →
APIs → Storage → Scaling → Bottlenecks → Trade-offs → Failure scenarios →
Interview discussion points.**

## Interview Relevance

This section *is* interview prep — architecture diagrams, tradeoffs, and a
consolidated question bank in [Tradeoff Discussions](./02-tradeoff-discussions.mdx).

## Done When

- [ ] You can whiteboard a RAG system end to end.
- [ ] You can defend key tradeoffs with reasons.
- [ ] Your portfolio clearly shows what you built and why.
