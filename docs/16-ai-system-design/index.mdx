portfolio that backs it up.

## The Design Framework (used throughout)

For every system, cover: **Requirements → High-level architecture → Data flow →
APIs → Storage → Scaling → Bottlenecks → Trade-offs → Failure scenarios →
Interview discussion points.**

## Interview Relevance

This section *is* interview prep — architecture diagrams, tradeoffs, and a
consolidated question bank in [Tradeoff Discussions](./02-tradeoff-discussions.mdx).

## Done When

- [ ] You can whiteboard a RAG system end to end.
- [ ] You can defend key tradeoffs with reasons.
- [ ] You can produce a defensible capacity and cost estimate from stated assumptions, in under 10 minutes.
- [ ] Your portfolio clearly shows what you built and why.
