## Phase 1 — LangChain Fundamentals

### Learn
- What LangChain is and the problem it solves (standardizing LLM app patterns: prompts, chains, memory, tools, retrieval).
- **LangChain vs LangGraph vs LlamaIndex** — know this cold:
  - **LangChain** — general-purpose LLM app framework (prompts, chains, tools, retrievers).
  - **LangGraph** — stateful, graph-based orchestration for agents and multi-step workflows (loops, branching, human-in-the-loop, persistence).
  - **LlamaIndex** — indexing/retrieval-first framework, strong for advanced RAG indexing strategies.
- Core building blocks: Models, Prompts, Chains/Runnables, Retrievers, Tools, Memory.
- Package structure: `langchain-core` (abstractions), `langchain` (chains/agents), `langchain-community` (integrations), `langchain-ollama` (Ollama-specific integration).
- Versioning note 🆕: LangChain moved most stable interfaces into `langchain-core`; know that imports have shifted across 0.1 → 0.3, and interviewers may ask why this split happened (stability + smaller dependency footprint for production).

### Interview Questions
- What problem does LangChain solve that raw API calls don't?
- When would you use LangChain vs plain Python + the model API?
- Why was `langchain-core` split out from `langchain`? 🆕

### Build
Simple FastAPI endpoint calling Ollama through LangChain.

## Phase 4 — LCEL (Most Important)

### Core Runnables

| Runnable | Purpose |
|---|---|
| `RunnableSequence` (`|`) | Chains steps into a pipeline. |
| `RunnableParallel` | Runs multiple branches concurrently. |
| `RunnablePassthrough` | Passes input through unchanged. |
| `RunnableLambda` | Wraps a custom Python function. |
| `RunnableBranch` | Conditional routing logic. |
| `.assign()` | Adds computed values into the pipeline dict. |
| `RunnableConfig` 🆕 | Passes runtime config (callbacks, tags, metadata, `run_name`) through a chain — key for tracing/observability. |
| `.batch()` / `.abatch()` 🆕 | Run a chain over many inputs concurrently — asked in cost/throughput questions. |
| `.with_retry()` 🆕 | Built-in retry wrapper around a Runnable for transient failures. |

### Interview Questions
- Explain LCEL and the `|` pipe operator.
- Why did LCEL replace the older `Chain` classes (e.g., `LLMChain`, `SequentialChain`)?
- How does `RunnableParallel` execute branches — sequentially or concurrently?
- How would you batch 1,000 requests through a chain efficiently? 🆕

### Build
Pipeline: `User → Retriever → Prompt → Model → Parser`.

## Phase 7 — Retrievers & Vector Stores

*(Connects directly with RAG — see the companion RAG roadmap for deep dives on embeddings, chunking, and evaluation.)*

### Learn
- Chroma integration, FAISS integration, Qdrant/pgvector integration.
- Retriever API (`.as_retriever()`), similarity search, MMR, metadata filters.
- **Advanced retrievers** 🆕:
  - `MultiVectorRetriever` — index multiple representations (summary + full chunk) per document.
  - `SelfQueryRetriever` — LLM translates a natural-language query into structured metadata filters automatically.
  - `EnsembleRetriever` — combines multiple retrievers (e.g., BM25 + vector) with weighted scoring.
  - `ContextualCompressionRetriever` — compresses/filters retrieved docs before returning them.

### Interview Questions
- Difference between a `VectorStore` and a `Retriever`.
- Why convert a vector store into a retriever instead of querying it directly?
- What does `SelfQueryRetriever` solve that a plain retriever can't? 🆕
- How would you combine BM25 and vector search results in LangChain? 🆕

## Phase 9 — Memory & Conversation History

### Learn

| Memory | Use |
|---|---|
| `ChatMessageHistory` | In-memory message store. |
| `RunnableWithMessageHistory` | Wraps a chain with session-based conversation state. |
| Postgres-backed memory | Persistent, durable history. |
| Redis-backed memory | Fast, session-scoped history. |
| LangGraph checkpointer 🆕 | The modern replacement for most legacy `Memory` classes — persists full graph state (not just messages), supports time-travel/rewind. |
| Summarization memory 🆕 | Compressing old turns into a running summary to control token growth in long conversations. |

### Interview Questions
- Conversation memory vs RAG — what's the difference in purpose?
- Session memory vs long-term/persistent memory.
- Why has LangChain pushed users toward LangGraph's checkpointer instead of the legacy `Memory` classes? 🆕

## Phase 10 — Streaming, Callbacks & Observability

## Phase 11 — Agents: AgentExecutor vs LangGraph 🆕

This distinction comes up constantly in 2026 interviews since LangChain has been steering people away from the legacy agent executor.

### Learn
- **Legacy `AgentExecutor`** — simple ReAct-style loop (think → act → observe), limited control over flow, no native persistence.
- **LangGraph agents** — the current recommended approach: explicit state graph, supports branching, loops, retries, human-in-the-loop interrupts, and durable checkpointing.
- ReAct pattern (Reason + Act) fundamentals — still the conceptual basis even inside LangGraph agents.
- When to use a simple LCEL chain vs a full agent (agents add cost/latency/unpredictability — only use them when the task genuinely needs dynamic tool selection or multi-step planning).

### Interview Questions
- Why has LangChain moved from `AgentExecutor` to LangGraph for agentic workflows?
- When would you *not* use an agent, even though one is possible?
- How does LangGraph enable human-in-the-loop approval before a risky action?

## Phase 12 — Testing, Evaluation & Caching 🆕

### Learn
- Unit testing chains with mocked LLM responses (`FakeListLLM`, `GenericFakeChatModel`).
- LangSmith datasets + evaluators for regression testing prompt/chain changes.
- Caching strategies to cut cost and latency on repeated queries.
- Golden-dataset testing — a fixed set of Q&A pairs run on every change to catch prompt regressions before deploy.

### Interview Questions
- How do you unit test a chain without calling a real LLM?
- How would you catch a regression after changing a prompt template?
- What caching layer would you add to cut LLM costs, and where in the pipeline?

## Phase 13 — Security & Production Hardening 🆕

### Learn
- Prompt injection risks when tool outputs or retrieved documents are untrusted.
- Sandboxing tool execution (e.g., a "calculator" tool that could otherwise `eval()` arbitrary code).
- Rate limiting and backoff for upstream model APIs.
- Secrets management (API keys never hard-coded, loaded via env/secret manager).
- Output validation before executing any tool with side effects (e.g., sending an email, deleting a record).

### Interview Questions
- How do you prevent a tool-calling agent from being manipulated by injected instructions in a retrieved document?
- How do you safely allow an LLM to trigger a side-effecting action (like a database write)?

### Learn

## Quick-Reference Cheat Sheet 🆕

**One-line answers for whiteboard/verbal rounds:**

- **LangChain** = standardized building blocks (prompts, models, chains, tools, memory, retrieval) for LLM apps.
- **LangGraph** = stateful graph orchestration for agents — use it when you need loops, branching, or persistence beyond a simple chain.
- **LCEL** = composable `Runnable` objects chained with `|`, with native support for streaming, batching, and async.
- **`RunnableParallel`** = fan-out multiple branches concurrently, then merge results.
- **`with_structured_output()`** = ask the model to return validated, typed data directly instead of parsing a raw string.
- **`SelfQueryRetriever`** = lets the LLM turn a natural-language question into metadata filters automatically.
- **`EnsembleRetriever`** = combine keyword (BM25) and vector search results with weighted fusion.
- **`AgentExecutor` → LangGraph** = the industry shift from a simple think-act loop to a fully controllable, persistent state graph.
- **LangSmith** = tracing and evaluation platform — inspect every step of a chain/agent run and catch prompt regressions.
- **Production checklist** = caching + retries/fallbacks + tracing + tool sandboxing + prompt versioning, not just "chain + model."
