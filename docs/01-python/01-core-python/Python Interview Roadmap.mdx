## Recommended Learning Order

1. **Core Python + Advanced Python basics.** Master objects, functions, OOP,
   exceptions, iterators, and decorators before moving on.
2. **DSA in parallel.** Solve a few problems every day. Revisit difficult
   patterns rather than just counting problems.
3. **Concurrency.** Learn threading, multiprocessing, and asyncio, then compare
   them through runnable examples (see
   [Python concurrency](../02-language-deep-dives/07-concurrency.mdx)).
4. **Backend engineering.** Build a tested FastAPI service with PostgreSQL,
   migrations, Redis, and a background worker.
5. **AI production patterns.** Add an LLM API, streaming, RAG, evaluations,
   tracing, and failure recovery.

## How to Answer in an Interview

**Concept questions** — use *definition → how it works → example → trade-off*:

> "A generator is a function that yields values lazily (definition). Calling it
> returns an iterator that runs until `yield`, then pauses and keeps its local
> state (how). That lets me stream a 10 GB file line by line (example), at the
> cost of single-pass iteration and no random access (trade-off)."

**Coding questions** — a repeatable routine:

1. **Clarify**: inputs, outputs, constraints, edge cases (empty, duplicates,
   negatives, huge input).
2. **Examples**: walk a small case by hand.
3. **Brute force first**: state it and its complexity.
4. **Optimize**: name the pattern (hash map, two pointers, heap, DP) and why.
5. **Code** cleanly, with meaningful names.
6. **Test** with your examples and edge cases, out loud.
7. **State** time and space complexity.

**Design questions** — requirements → API → data model → components →
concurrency → failure modes → security → scaling → observability → cost.

### Phase 1 — Interview Q&A and Snippets

**`==` vs `is`?** `==` compares *values* (calls `__eq__`); `is` compares
*identity* (same object in memory). Use `is` only for singletons such as
`None`: `if x is None`. Small-int and string caching makes `is` appear to work
on values, but that is an implementation detail; never rely on it.

**Mutable vs immutable?** Immutable objects (`int`, `str`, `tuple`,
`frozenset`, `bytes`) can't change after creation; mutable ones (`list`,
`dict`, `set`) can. A tuple can hold a list, and that list can still be
mutated, because the tuple only holds *references*.

**What's the mutable default argument bug?** Defaults are evaluated **once**, at
function definition, so a mutable default is shared across calls:

```python
def add(item, bucket=[]):          # ❌ one shared list
    bucket.append(item)
    return bucket

add(1); add(2)                      # second call returns [1, 2]

def add(item, bucket=None):        # ✅
    if bucket is None:
        bucket = []
    bucket.append(item)
    return bucket
```

**Shallow vs deep copy?** A shallow copy duplicates the outer container but
shares the inner objects; a deep copy recursively duplicates everything.

```python
import copy
a = [[1, 2], [3]]
b = copy.copy(a)
b[0].append(99)
print(a)                  # [[1, 2, 99], [3]]  — inner list is shared
c = copy.deepcopy(a)      # fully independent
```

**What is LEGB and what's the late-binding closure gotcha?** Name lookup goes
Local → Enclosing → Global → Built-in. Closures capture *variables*, not
values, so they see the variable's value at call time:

```python
funcs = [lambda: i for i in range(3)]
print([f() for f in funcs])               # [2, 2, 2]

funcs = [lambda i=i: i for i in range(3)] # bind the current value
print([f() for f in funcs])               # [0, 1, 2]
```

**What is the MRO and what does `super()` do?** The MRO is the order Python
searches base classes, computed by **C3 linearization** (`Class.__mro__`).
`super()` doesn't mean "the parent": it means "the *next* class in the MRO",
which is what makes cooperative multiple inheritance work.

**Iterable vs iterator vs generator?** An *iterable* has `__iter__` and can
produce an iterator; an *iterator* has `__next__` and `__iter__`, remembers its
position, and raises `StopIteration` when done; a *generator* is an iterator
created by a function with `yield` (or a generator expression), which pauses and
resumes while keeping local state.

```python
def read_lines(path):
    with open(path) as f:
        for line in f:            # lazy: one line at a time, constant memory
            yield line.rstrip("\n")

total = sum(len(line) for line in read_lines("big.log"))
```

**How do you write a decorator, and why `functools.wraps`?** A decorator is a
function that takes a function and returns a wrapper. `wraps` preserves the
original's name, docstring, and signature metadata:

```python
import functools, time

def timed(fn):
    @functools.wraps(fn)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        try:
            return fn(*args, **kwargs)
        finally:
            print(f"{fn.__name__} took {time.perf_counter() - start:.3f}s")
    return wrapper

def retry(times: int):                      # decorator WITH arguments: one extra level
    def decorator(fn):
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):
            for attempt in range(times):
                try:
                    return fn(*args, **kwargs)
                except ConnectionError:
                    if attempt == times - 1:
                        raise
        return wrapper
    return decorator

@retry(3)
@timed
def fetch(): ...
```

**Exceptions: `else`, `finally`, chaining?** `else` runs only if the `try`
raised nothing; `finally` always runs (cleanup). Use `raise NewError(...) from
exc` to keep the original cause visible in the traceback.

```python
class ConfigError(Exception): ...

def load(path):
    try:
        with open(path) as f:
            return parse(f.read())
    except FileNotFoundError as exc:
        raise ConfigError(f"missing config: {path}") from exc
```

**Why avoid `except Exception: pass`?** It hides real bugs, swallows errors you
didn't anticipate, and makes failures silent. Catch specific exceptions, log
unexpected ones, and let them propagate if you can't handle them.

**What makes an object hashable?** It has a stable `__hash__` consistent with
`__eq__`; practically, it must be immutable. That's why lists can't be dict keys
but tuples of immutables can.

### Phase 2 — Cheat Sheet and Pattern Snippets

**Complexity of common Python operations**

| Operation | Complexity |
| --- | --- |
| `list.append`, `list.pop()` (end) | O(1) amortized |
| `list.insert(0, x)`, `list.pop(0)` | O(n) — use `deque` instead |
| `x in list` | O(n) |
| `x in set`, `x in dict`, dict get/set | O(1) average, O(n) worst |
| `list.sort()`, `sorted()` | O(n log n) |
| `deque.append`, `appendleft`, `popleft` | O(1) |
| `heapq.heappush`, `heappop` | O(log n) |
| `heapq.heapify` | O(n) |
| Slicing `a[i:j]` | O(j - i) (copies) |
| String `+=` in a loop | O(n²) overall — use `"".join(parts)` |

| --- | --- |

**Hash map — Two Sum (O(n))**

```python
def two_sum(nums: list[int], target: int) -> list[int]:
    seen: dict[int, int] = {}
    for i, n in enumerate(nums):
        if target - n in seen:
            return [seen[target - n], i]
        seen[n] = i
    return []
```

**Sliding window — longest substring without repeats (O(n))**

```python
def longest_unique(s: str) -> int:
    last: dict[str, int] = {}
    start = best = 0
    for i, ch in enumerate(s):
        if ch in last and last[ch] >= start:
            start = last[ch] + 1            # shrink window past the duplicate
        last[ch] = i
        best = max(best, i - start + 1)
    return best
```

**Binary search (O(log n))**

```python
def bsearch(a: list[int], x: int) -> int:
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == x:
            return mid
        if a[mid] < x:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1
```

**Kadane — maximum subarray (O(n))**

```python
def max_subarray(nums: list[int]) -> int:
    cur = best = nums[0]
    for n in nums[1:]:
        cur = max(n, cur + n)               # extend or restart
        best = max(best, cur)
    return best
```

**LRU cache (O(1) get/put)**

```python
from collections import OrderedDict

class LRUCache:
    def __init__(self, capacity: int):
        self.cap = capacity
        self.data: OrderedDict[int, int] = OrderedDict()

    def get(self, key: int) -> int:
        if key not in self.data:
            return -1
        self.data.move_to_end(key)          # mark most recently used
        return self.data[key]

    def put(self, key: int, value: int) -> None:
        self.data[key] = value
        self.data.move_to_end(key)
        if len(self.data) > self.cap:
            self.data.popitem(last=False)   # evict least recently used
```

Be ready to also build it from a hash map plus a doubly linked list, since many
interviewers ask for that version.

**Top K frequent (heap or Counter)**

```python
import heapq
from collections import Counter

def top_k_frequent(nums: list[int], k: int) -> list[int]:
    counts = Counter(nums)
    return heapq.nlargest(k, counts, key=counts.get)    # O(n log k)
```

**BFS (graph traversal / shortest path in unweighted graphs)**

```python
from collections import deque

def bfs(graph: dict[str, list[str]], start: str) -> list[str]:
    seen = {start}
    queue = deque([start])
    order = []
    while queue:
        node = queue.popleft()
        order.append(node)
        for nb in graph[node]:
            if nb not in seen:
                seen.add(nb)
                queue.append(nb)
    return order
```

**Topological sort (Kahn's algorithm)**

```python
from collections import deque

def topo_sort(n: int, edges: list[tuple[int, int]]) -> list[int]:
    adj = [[] for _ in range(n)]
    indegree = [0] * n
    for a, b in edges:                      # a must come before b
        adj[a].append(b)
        indegree[b] += 1
    queue = deque(i for i in range(n) if indegree[i] == 0)
    order = []
    while queue:
        node = queue.popleft()
        order.append(node)
        for nb in adj[node]:
            indegree[nb] -= 1
            if indegree[nb] == 0:
                queue.append(nb)
    return order if len(order) == n else []     # empty means a cycle exists
```

**Dynamic programming — coin change (bottom-up)**

```python
def coin_change(coins: list[int], amount: int) -> int:
    INF = amount + 1
    dp = [0] + [INF] * amount               # dp[a] = fewest coins to make a
    for a in range(1, amount + 1):
        for c in coins:
            if c <= a:
                dp[a] = min(dp[a], dp[a - c] + 1)
    return dp[amount] if dp[amount] != INF else -1
```

DP recipe: **define the state → write the transition → set base cases → pick
the order → optimize space**. Start with plain recursion, add memoization
(`functools.cache`), then convert to a table.

**Union-find**

```python
class DSU:
    def __init__(self, n: int):
        self.parent = list(range(n))

    def find(self, x: int) -> int:
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]    # path compression
            x = self.parent[x]
        return x

    def union(self, a: int, b: int) -> bool:
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False
        self.parent[rb] = ra
        return True
```

**Edge cases checklist:** empty input, single element, duplicates, negative
numbers, all equal values, already sorted / reverse sorted, very large input
(overflow isn't an issue in Python, but time is), and `None` or invalid input.

**How does CPython manage memory?** Primarily **reference counting**: each
object tracks how many references point to it and is freed when the count hits
zero. Reference counting can't free **cycles** (A refers to B refers to A), so a
supplementary **cyclic garbage collector** periodically finds and frees
unreachable cycles. `weakref` lets you reference an object *without* keeping it
alive, which is useful for caches and observer lists. `__del__` is unreliable
(timing, cycles, interpreter shutdown), so prefer context managers for cleanup.

```python
import tracemalloc

tracemalloc.start()
data = [str(i) * 10 for i in range(100_000)]
current, peak = tracemalloc.get_traced_memory()
print(f"current={current / 1e6:.1f}MB peak={peak / 1e6:.1f}MB")
```

**Context managers — class vs `contextlib`:**

```python
from contextlib import contextmanager
import time

class Timer:
    def __enter__(self):
        self.start = time.perf_counter()
        return self
    def __exit__(self, exc_type, exc, tb):
        self.elapsed = time.perf_counter() - self.start
        return False                    # False/None: don't suppress exceptions

@contextmanager
def transaction(conn):
    try:
        yield conn
        conn.commit()
    except Exception:
        conn.rollback()
        raise
```

`ExitStack` manages a *dynamic* number of context managers (for example
opening N files). Async resources use `async with` with `__aenter__` /
`__aexit__` (or `contextlib.asynccontextmanager`).

**Generator pipelines are lazy and memory-efficient:**

```python
def read(path):
    with open(path) as f:
        yield from f

def parse(lines):
    for line in lines:
        yield line.split(",")

def only_errors(rows):
    return (r for r in rows if r[2] == "ERROR")

for row in only_errors(parse(read("app.log"))):    # one row in memory at a time
    handle(row)
```

**Type hints, `Protocol`, and static vs runtime checking:** type hints are
ignored at runtime; tools like mypy/Pyright check them statically. A
**`Protocol`** gives structural typing ("if it has these methods, it fits"),
which suits duck-typed Python and dependency injection:

```python
from typing import Protocol

class Embedder(Protocol):
    def embed(self, texts: list[str]) -> list[list[float]]: ...

class OllamaEmbedder:
    def embed(self, texts: list[str]) -> list[list[float]]:
        ...

def build_index(embedder: Embedder, docs: list[str]):    # accepts anything matching
    return embedder.embed(docs)
```

Use **Pydantic** where you need *runtime* validation of untrusted data (API
input, config, LLM output); use **dataclasses** for lightweight internal
structures:

```python
from dataclasses import dataclass, field

@dataclass(frozen=True, slots=True)
class Chunk:
    doc_id: str
    text: str
    tags: tuple[str, ...] = ()            # immutable default; use default_factory for lists
```

**Descriptors** power `@property`, methods, and ORM fields. An object with
`__get__`/`__set__` defined on a *class* controls attribute access on instances:

```python
class Positive:
    def __set_name__(self, owner, name):
        self.name = "_" + name
    def __get__(self, obj, objtype=None):
        return self if obj is None else getattr(obj, self.name)
    def __set__(self, obj, value):
        if value <= 0:
            raise ValueError("must be positive")
        setattr(obj, self.name, value)

class Order:
    quantity = Positive()
```

**`__new__` vs `__init__`:** `__new__` *creates* the instance (used for
singletons, immutable subclasses); `__init__` *initializes* it. **Metaclasses**
are "classes of classes"; they're rarely the right tool (prefer decorators or
`__init_subclass__`) but explain frameworks like ORMs and Enums.

**What's the GIL, and what changes with free-threaded Python?** The GIL lets one
thread execute Python bytecode at a time in standard CPython, so CPU-bound
threads don't run in parallel; I/O-bound threads still help because the GIL is
released while waiting. Free-threaded builds (experimental in recent versions)
remove that limit, but default builds still have it and the ecosystem is still
adapting.

**Design patterns that map naturally to Python:** *Strategy* (pass a function or
object), *Factory* (a function or classmethod returning instances), *Adapter*
(wrap a provider SDK behind your interface), *Observer* (callbacks/signals), and
*Dependency Injection* (pass dependencies in, as FastAPI's `Depends` does).

### Phase 4 — Model Answers and Snippets

:::note
This phase has a dedicated deep-dive: [Python concurrency](../02-language-deep-dives/07-concurrency.mdx).
Below are concise model answers to the scenario list.

**Choosing the tool:** I/O-bound with many concurrent operations and async
libraries → `asyncio`; I/O-bound with only blocking libraries → threads;
CPU-bound → processes. Always measure first.

**Why doesn't `async def` make code non-blocking?** `async def` only makes a
function *awaitable*. If the body calls blocking code (`time.sleep`,
`requests.get`, a sync DB driver, a CPU loop), it holds the single event-loop
thread and everything else stalls. It's non-blocking only if it `await`s
non-blocking operations. Fix: use async libraries, or offload with
`asyncio.to_thread()` / a process pool.

**Why does the GIL matter?** Only one thread runs Python bytecode at a time, so
CPU-bound threads gain no parallelism. I/O-bound threads still overlap because
the GIL is released while waiting.

**1,000 API calls with bounded concurrency:**

```python
import asyncio, httpx

async def fetch_all(urls: list[str], limit: int = 20):
    sem = asyncio.Semaphore(limit)

    async with httpx.AsyncClient(timeout=10) as client:
        async def fetch(url: str):
            async with sem:                          # at most `limit` in flight
                resp = await client.get(url)
                resp.raise_for_status()
                return resp.json()

        return await asyncio.gather(*(fetch(u) for u in urls), return_exceptions=True)
```

For far larger inputs, avoid creating all tasks up front: use a bounded
`asyncio.Queue` with a fixed number of workers.

**Prevent a shared counter losing updates:** `counter += 1` is read-modify-write
and not atomic. Protect it with a `threading.Lock` (threads) or
`multiprocessing.Value` with its lock (processes); better, avoid shared state by
having workers return partial results and combine them, or funnel updates
through a queue. In `asyncio`, a plain increment between awaits is safe, but a
read, `await`, write sequence is not.

```python
import threading

lock = threading.Lock()
counter = 0

def increment():
    global counter
    with lock:
        counter += 1
```

**Cancel a group of tasks safely:** use `asyncio.TaskGroup` (failure cancels
siblings automatically) or cancel tasks and then `await asyncio.gather(*tasks,
return_exceptions=True)` to let them clean up. Handle `CancelledError` only to
clean up in `finally`, and **re-raise it**.

**Stop workers at shutdown:** handle `SIGTERM`, stop accepting new work, drain
the queue with a timeout shorter than the platform's grace period, cancel the
workers, and await them.

```python
import asyncio, signal

async def main():
    stop = asyncio.Event()
    loop = asyncio.get_running_loop()
    for sig in (signal.SIGINT, signal.SIGTERM):
        loop.add_signal_handler(sig, stop.set)

    q: asyncio.Queue = asyncio.Queue(maxsize=100)
    workers = [asyncio.create_task(worker(q)) for _ in range(8)]

    await stop.wait()
    await asyncio.wait_for(q.join(), timeout=25)
    for w in workers:
        w.cancel()
    await asyncio.gather(*workers, return_exceptions=True)
```

**Prevent a queue growing without limit:** use a **bounded** queue
(`maxsize`) so producers block (`await q.put`) when it's full — that's
backpressure. At a system edge, shed load with `429`/`503`; for durable work use
an external broker.

**Amdahl's law:** speedup is limited by the serial fraction `s` of the work:
`speedup = 1 / (s + (1 - s) / n)`. If 10% of the work is serial, even infinite
cores cap the speedup at 10x.

### Phase 5 — Interview Q&A and Snippets

**`async def` vs `def` route handlers in FastAPI?** `async def` runs on the event
loop and must only await non-blocking code. Plain `def` runs in a worker thread
pool, so blocking libraries won't freeze the server. Use `def` for sync
libraries, `async def` for async ones.

**How does `Depends` work, and why is it good for testing?** FastAPI resolves
dependencies per request (and caches them within a request). Because endpoints
get collaborators through `Depends`, tests can swap them with
`app.dependency_overrides`:

```python
from fastapi import Depends, FastAPI
from sqlalchemy.ext.asyncio import AsyncSession

app = FastAPI()

async def get_session():
    async with SessionLocal() as session:        # one session per request
        yield session

@app.get("/users/{user_id}")
async def read_user(user_id: int, session: AsyncSession = Depends(get_session)):
    ...

# in tests
app.dependency_overrides[get_session] = get_test_session
```

**Pydantic validation example:**

```python
from pydantic import BaseModel, Field, field_validator

class UserIn(BaseModel):
    email: str
    age: int = Field(ge=18, le=120)

    @field_validator("email")
    @classmethod
    def normalize_email(cls, v: str) -> str:
        if "@" not in v:
            raise ValueError("invalid email")
        return v.lower()
```

Use separate **DTOs** (request/response schemas) from **database models** so
API contracts and storage can evolve independently and you never leak internal
fields like password hashes.

**ACID and isolation levels?** Atomicity (all or nothing), Consistency
(constraints hold), Isolation (concurrent transactions don't interfere
incorrectly), Durability (committed data survives crashes).

| Anomaly | Meaning | Prevented by |
| --- | --- | --- |
| Dirty read | Read another transaction's uncommitted data | Read Committed and above |
| Non-repeatable read | Same row read twice gives different values | Repeatable Read and above |
| Phantom read | Same query returns different rows | Serializable (and PostgreSQL's Repeatable Read) |

PostgreSQL's default is **Read Committed**. For lost updates use `SELECT ...
FOR UPDATE` (**pessimistic** locking) or a **version column** checked on update
(**optimistic** locking), and retry on serialization failures or deadlocks.

**Why do indexes help and what do they cost?** A B-tree index turns a scan into
a log-time lookup for filters, joins, and sorts. Costs: slower writes, more
storage. Use `EXPLAIN ANALYZE` to see whether a query uses an index; index
columns used in `WHERE`, `JOIN`, and `ORDER BY`; composite index column order
matters.

**Pagination:** offset pagination (`LIMIT/OFFSET`) is simple but gets slow and
inconsistent on large or changing tables; **cursor (keyset) pagination**
(`WHERE id > :last_id ORDER BY id LIMIT n`) is stable and fast.

**N+1 queries?** Loading a list and then lazily querying related rows for each
item (1 query + N). Fix with eager loading or a join:

```python
from sqlalchemy import select
from sqlalchemy.orm import selectinload

stmt = select(Author).options(selectinload(Author.books))   # 2 queries instead of N+1
authors = (await session.scalars(stmt)).all()
```

In **async** SQLAlchemy, implicit lazy loading raises errors, so load
relationships explicitly.

**SQL injection prevention:** always use parameterized queries or the ORM;
never build SQL with string formatting.

```python
from sqlalchemy import text

await session.execute(
    text("SELECT * FROM users WHERE email = :email"),
    {"email": email},                      # ✅ bound parameter
)
# ❌ text(f"SELECT * FROM users WHERE email = '{email}'")
```

**Testing with pytest — fixtures, parametrize, mocking:**

```python
import pytest
from fastapi.testclient import TestClient
from unittest.mock import AsyncMock

@pytest.fixture
def client():
    app.dependency_overrides[get_llm] = lambda: FakeLlm()
    with TestClient(app) as c:
        yield c
    app.dependency_overrides.clear()

@pytest.mark.parametrize("question,status", [("hi", 200), ("", 422)])
def test_ask_validation(client, question, status):
    assert client.post("/ask", json={"question": question}).status_code == status

async def test_retry_on_timeout():

    assert await call_with_retry(llm) == "ok"
```

Know the test pyramid (many unit tests, fewer integration, few end-to-end),
isolate DB tests (transaction rollback per test or a throwaway database), mock
**at the boundary** (HTTP/LLM clients), and mention coverage as a signal, not a
goal.

**Cache-aside pattern:**

```python
import json

async def get_user(uid: int):
    key = f"user:{uid}"
    cached = await redis.get(key)
    if cached:
        return json.loads(cached)
    user = await db_get_user(uid)                # cache miss → load from DB
    await redis.set(key, json.dumps(user), ex=300)   # TTL bounds staleness
    return user
```

Invalidate or update the key on writes. **Cache stampede**: a hot key expires and
many requests hit the DB at once — mitigate with single-flight/locking, jittered
TTLs, or refreshing early.

**Idempotency keys:** the client sends a unique key per logical operation; the
server stores the key and the result, and a repeated request returns the stored
result instead of executing again. This makes retries safe for `POST` calls like
payments.

```python
@app.post("/payments")
async def create_payment(body: PaymentIn, idempotency_key: str = Header(...)):
    first_time = await redis.set(f"idem:{idempotency_key}", "processing", nx=True, ex=86400)
    if not first_time:
        return await stored_response(idempotency_key)     # replay prior outcome
    result = await process_payment(body)
    await store_response(idempotency_key, result)
    return result
```

**`BackgroundTasks` vs a task queue:** `BackgroundTasks` run in the same process
after the response, and are lost if the process dies, with no retries or
visibility. For work that must not be lost, is long-running, or needs retries,
use a durable queue (Celery/RQ/Dramatiq) with a broker.

**Delivery guarantees:** *at-most-once* (may lose messages), *at-least-once*
(may duplicate; the common default), *exactly-once* (hard; usually approximated
with at-least-once plus **idempotent consumers**). Use acks, retries with
backoff, and a **dead-letter queue** for poison messages. The **outbox
pattern** writes the event to an `outbox` table in the same DB transaction as the
state change, and a separate relay publishes it, avoiding "DB committed but
message not sent".

**JWT and passwords:** hash passwords with a slow, salted algorithm (argon2 or
bcrypt), never plain or fast hashes. JWTs are *signed*, not encrypted: don't put
secrets in them; use short-lived access tokens plus refresh tokens; validate
signature, expiry, audience, and issuer. **Authentication** = who you are;
**authorization** = what you may do (role-based and resource-based checks).

**CORS vs CSRF:** CORS is a browser policy controlling which origins may *read*
cross-origin responses; it is not authentication. CSRF is an attack where a
browser auto-sends cookies to your site from a malicious page; defend with
SameSite cookies and CSRF tokens (less relevant for bearer-token APIs).

**Other security items to be able to discuss:** SSRF (validate and restrict
outbound URLs you fetch), unsafe deserialization (never unpickle untrusted data),
rate limiting and quotas, request size limits, secrets in a secret manager, and
logs that never contain tokens or PII. For timeouts, retries, circuit breakers,
and bulkheads see [API & service design](../../08-llm-application-development/02-api-service-design.mdx).

### Phase 6 — Interview Q&A and Snippets

**LLM call parameters:** `temperature` controls randomness (low for extraction
and deterministic tasks, higher for creative); `top_p` samples from the smallest
set of tokens whose probability mass reaches p (tune temperature *or* top_p, not
both aggressively); `max_tokens` caps output length and cost. Know the roles of
system (rules and persona), user (the request), and developer/tool messages, and
that the context window includes **input + output** tokens.

**Reliable structured output:** request JSON/schema output where the provider
supports it, validate with Pydantic, and re-ask a bounded number of times:

```python
from pydantic import BaseModel, ValidationError

class Extraction(BaseModel):
    title: str
    tags: list[str]

async def extract(text: str, max_attempts: int = 2) -> Extraction:
    for _ in range(max_attempts):
        raw = await llm(f"Return JSON with title and tags for:\n{text}")
        try:
            return Extraction.model_validate_json(raw)
        except ValidationError:
            continue
    raise ValueError("model failed to return valid JSON")
```

**What is RAG and how do the pieces fit?** Retrieval-Augmented Generation:
**ingest** (load → clean → chunk → embed → store with metadata) then **query**
(embed question → retrieve top-k → optionally rerank → assemble context →
generate with citations). It grounds answers in your data and reduces
hallucination without retraining.

**Chunking trade-offs:** small chunks → precise matches but lost context; large
chunks → more context but noisier retrieval and more tokens. Use overlap so
sentences at boundaries aren't lost, split on semantic boundaries (headings,
paragraphs) where possible, and tune against an evaluation set rather than by
guessing.

**Similarity metrics:** cosine similarity measures angle (magnitude-independent);
dot product equals cosine for normalized vectors and is faster; Euclidean
measures distance. Use the metric the embedding model was trained for.

```python
import math

def cosine(a: list[float], b: list[float]) -> float:
    dot = sum(x * y for x, y in zip(a, b))
    return dot / (math.sqrt(sum(x * x for x in a)) * math.sqrt(sum(y * y for y in b)))
```

**Dense vs sparse vs hybrid retrieval:** dense (embeddings) captures meaning but
can miss exact terms (ids, names, error codes); sparse (BM25/keyword) nails exact
terms but misses paraphrases; **hybrid** combines both. A simple, robust fusion
method is **Reciprocal Rank Fusion**:

```python
def rrf(rankings: list[list[str]], k: int = 60) -> list[str]:
    scores: dict[str, float] = {}
    for ranking in rankings:
        for rank, doc_id in enumerate(ranking, start=1):
            scores[doc_id] = scores.get(doc_id, 0.0) + 1.0 / (k + rank)
    return sorted(scores, key=scores.get, reverse=True)

fused = rrf([dense_ids, bm25_ids])
```

A **reranker** (cross-encoder) then rescoring the top ~20–50 candidates improves
precision at higher latency and cost. **Query rewriting** (expanding or
decomposing the question) helps vague or multi-part queries.

**RAG evaluation metrics:**

| Metric | Meaning |
| --- | --- |
| precision@k | Fraction of the top k results that are relevant |
| recall@k | Fraction of *all* relevant docs found in the top k |
| MRR | Mean of 1 / rank of the first relevant result |
| NDCG | Rewards relevant results ranked higher, graded relevance, normalized |
| Faithfulness / groundedness | Is every claim in the answer supported by the retrieved context? |
| Answer relevance | Does the answer actually address the question? |

```python
def recall_at_k(retrieved: list[str], relevant: set[str], k: int) -> float:
    return len(set(retrieved[:k]) & relevant) / len(relevant) if relevant else 0.0

def reciprocal_rank(retrieved: list[str], relevant: set[str]) -> float:
    for rank, doc_id in enumerate(retrieved, start=1):
        if doc_id in relevant:
            return 1.0 / rank
    return 0.0
```

Evaluate **retrieval and generation separately** to find the failing stage. Build
a **golden dataset** of questions with expected sources/answers; use
**LLM-as-a-judge** (RAGAS, DeepEval) for faithfulness and relevance, but
calibrate it against human labels; run evaluations in CI to catch regressions
when changing models, prompts, or chunking.

**Tenant isolation in RAG:** enforce permissions in the **retrieval query**,
using identity from the authenticated token, never from user-supplied input and
never by asking the model to hide data:

```python
results = collection.query(
    query_embeddings=[vector],
    n_results=5,
    where={"tenant_id": auth.tenant_id},     # server-side, from the verified token
)
```

**Incremental ingestion and consistency:** use deterministic chunk ids (for
example a hash of doc id + chunk index + content) so re-ingestion **upserts**
instead of duplicating; store a content hash per document to skip unchanged
files; when a document changes or is deleted, delete its old chunks. Keep the
relational source of truth and the vector index in sync (outbox pattern or
ingestion status tracking), and version the index when you change the embedding
model.

**Workflow vs agent:** a **workflow** follows predefined steps (predictable,
cheaper, easier to test); an **agent** lets the model decide which tools to call
in a loop (flexible, but less predictable and costlier). Prefer a workflow when
the steps are known; use an agent when the path genuinely varies.

**Agent loop with safety limits:**

```python
async def run_agent(messages: list[dict], max_steps: int = 6) -> str:
    for _ in range(max_steps):                               # hard iteration cap
        resp = await llm(messages, tools=TOOLS)
        if not resp.tool_calls:
            return resp.content
        for call in resp.tool_calls:
            args = TOOL_SCHEMAS[call.name].model_validate(call.arguments)   # validate
            check_permission(user, call.name)                              # least privilege
            result = await TOOLS_IMPL[call.name](args)                     # idempotent tools
            messages.append(tool_result_message(call, result))
    raise AgentLimitError("exceeded max steps")
```

Add timeouts per tool, a token/cost budget, **human-in-the-loop approval** for
irreversible actions, **checkpointing** state (LangGraph) so runs can resume, and
tracing (LangSmith/OpenTelemetry) for debugging. Treat tool output and retrieved
text as **untrusted** (prompt injection); see
[Logging, monitoring & guardrails](../../13-production-genai-and-llmops/04-logging-monitoring-guardrails.mdx).

**MCP (Model Context Protocol):** a standard for exposing tools, resources, and
prompts to AI clients. An MCP **server** exposes capabilities; an MCP **client**
(inside the host app) discovers and calls them. Be ready to discuss discovery,
permissions, and trusting third-party servers.

**Production AI architecture talking points:** separate the **API layer**
(auth, validation, streaming), **orchestration layer** (workflows/agents,
retrieval), and **inference layer** (model servers/providers) so each scales and
fails independently; run **ingestion as background workers** fed by a queue;
bound concurrent model calls with semaphores and queues; cache embeddings and
(where safe) answers; add retries, circuit breakers, and **provider fallback**;
track **tokens, latency, and cost** per request and per tenant; stream responses
and handle client disconnects; version models, prompts, and indexes; degrade
gracefully (return retrieved passages if generation is down).

**Testing AI code:** mock the provider at the HTTP/client boundary with
deterministic fixtures; unit-test chunking, prompt assembly, and parsers as
normal code; use golden datasets for retrieval and answer quality; run adversarial
prompt tests (injection, jailbreak, data-exfiltration probes) in CI; regression
test across model versions; balance the **latency / cost / quality** triangle
explicitly; use offline evals before release and online monitoring (feedback,
no-answer rate, tracing) after.

**Observability and delivery:** structured logs with request ids, metrics (p50/p95/p99
latency, error rate, tokens, cache hit rate), OpenTelemetry traces across stages,
liveness vs readiness probes, SLOs with error budgets, canary releases for
prompt and model changes, and a rollback path. See
[Deployment basics](../../13-production-genai-and-llmops/05-deployment-basics.mdx) and
[Logging, monitoring & guardrails](../../13-production-genai-and-llmops/04-logging-monitoring-guardrails.mdx).

## Common Mistakes in Interviews

- Jumping to code without clarifying requirements and edge cases.
- Saying "use async" without naming what is blocking and why async helps.
- Not stating time and space complexity (or getting it wrong for built-ins).
- Memorizing solutions instead of learning patterns, then freezing on variations.
- Ignoring failure modes: timeouts, retries, partial failure, idempotency.
- Treating AI components as magic: no evaluation plan, no cost or latency
  discussion, no injection defenses.
- Overengineering the design (Kafka and Kubernetes for a small service) without
  justifying it from requirements.
- Not explaining trade-offs, since senior interviews grade the reasoning more
  than the final answer.

## Things to Remember

- Tick a checklist item only when you can explain it and code it from memory.
- Patterns beat problem counts: learn to recognize *which pattern fits*.
- Always say complexity, edge cases, and trade-offs out loud.
- Concurrency: **I/O → async/threads, CPU → processes**; bound everything.
- Backend: validate input, parameterize SQL, make retries safe with idempotency.
- AI systems: retrieval quality, evaluation, guardrails, and cost control matter
  as much as the model.
- For designs, follow the template: requirements → API → data → architecture →
  concurrency → failures → security → scale → observability → cost.
