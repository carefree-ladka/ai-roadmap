## What Is It?

Automated tests verify your code does what you expect. Debugging is the process
of locating and fixing defects.

## Why Does It Matter?

Tests let you change code confidently. In AI/RAG systems they pin down
behavior (retrieval, parsing, API contracts) that's otherwise easy to break.

## pytest Basics

```python
# app/math_utils.py
def add(a: int, b: int) -> int:
    return a + b
```

```python
# tests/test_math_utils.py
from app.math_utils import add

def test_add():
    assert add(2, 3) == 5
```

Run it:

```bash
pip install pytest
pytest -q
```

pytest discovers files named `test_*.py` and functions named `test_*`.

## Testing Exceptions

```python
import pytest

def test_withdraw_rejects_overdraw():
    with pytest.raises(ValueError, match="insufficient"):
        withdraw(balance=10, amount=50)
```

## Fixtures

Fixtures provide reusable setup/teardown:

```python
import pytest

@pytest.fixture
def sample_user():
    return {"name": "Ada", "roles": ["admin"]}

def test_is_admin(sample_user):
    assert "admin" in sample_user["roles"]
```

Fixtures can yield for teardown:

```python
@pytest.fixture
def temp_db():
    db = create_db()
    yield db
    db.close()          # runs after the test
```

## Parametrization

Run one test across many inputs:

```python
import pytest

@pytest.mark.parametrize("a,b,expected", [
    (1, 1, 2),
    (2, 3, 5),
    (-1, 1, 0),
])
def test_add(a, b, expected):
    assert add(a, b) == expected
```

## Mocking

Replace slow/external dependencies:

```python
from unittest.mock import patch

def test_get_weather_uses_api():
    with patch("app.weather.httpx.get") as mock_get:
        mock_get.return_value.json.return_value = {"temp": 20}
        assert get_weather("NYC") == 20
```

## Unit vs Integration Tests

- **Unit test**: one function/class in isolation; dependencies mocked. Fast.
- **Integration test**: multiple parts together (e.g. API + DB). Slower, higher confidence.

## Testing Async Code

```bash
pip install pytest-asyncio
```

```python
import pytest

@pytest.mark.asyncio
async def test_fetch_user():
    user = await fetch_user(1)
    assert user["id"] == 1
```

## Test Organization

```text
project/
├── app/
│   └── ...
└── tests/
    ├── conftest.py        # shared fixtures
    ├── unit/
    └── integration/
```

`conftest.py` holds fixtures shared across tests automatically.

## Debugging Techniques

```python
breakpoint()          # drops into the debugger (pdb) at this line
```

Common pdb commands: `n` (next), `s` (step in), `c` (continue), `p expr`
(print), `l` (list source), `q` (quit).

Other tactics:

- Read the **full** traceback bottom-up; the last line names the error.
- Add targeted logging instead of scattered `print`.
- Reproduce with the **smallest** failing input.

## Common Mistakes

- Tests that depend on each other or on execution order.
- Over-mocking until tests assert nothing real.
- No async plugin, so `async def` tests silently don't run.
- Asserting on implementation details instead of behavior.

- Test behavior, not internals.
- Fixtures for setup; parametrize for many inputs.
- `pytest-asyncio` + `@pytest.mark.asyncio` for coroutines.
