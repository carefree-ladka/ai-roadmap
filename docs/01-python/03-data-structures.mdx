## What Is It?

Python's built-in containers: `list`, `tuple`, `set`, and `dict`, plus the
operations that make them powerful.

## Why Does It Matter?

Choosing the right structure changes both correctness and speed. Interviews
love "list vs tuple" and "how do you dedupe?".

## Core Structures

| Type | Ordered | Mutable | Duplicates | Typical use |
| --- | --- | --- | --- | --- |
| `list` | Yes | Yes | Yes | Ordered sequence |
| `tuple` | Yes | No | Yes | Fixed record, dict key |
| `set` | No* | Yes | No | Membership, dedupe |
| `dict` | Yes (3.7+) | Yes | Keys unique | Key → value map |

\*Sets have no meaningful order.

### list

```python
nums = [3, 1, 2]
nums.append(4)
nums.sort()            # [1, 2, 3, 4]  (in place)
top = sorted(nums, reverse=True)
```

### tuple

```python
point = (3, 4)
x, y = point           # unpacking
# point[0] = 9         # TypeError: immutable
```

### set

```python
tags = {"ai", "python", "ai"}   # {"ai", "python"}
"ai" in tags                     # True (O(1) average)
{"a", "b"} & {"b", "c"}          # {"b"} intersection
```

### dict

```python
user = {"name": "Ada", "age": 36}
user["email"] = "ada@example.com"
user.get("phone", "N/A")         # safe access with default
for key, value in user.items():
    print(key, value)
```

## Nested Structures

```python
users = [
    {"name": "Ada", "roles": ["admin"]},
    {"name": "Alan", "roles": ["user"]},
]
users[0]["roles"][0]             # "admin"
```

## Slicing

```python
letters = ["a", "b", "c", "d", "e"]
letters[1:3]     # ['b', 'c']
letters[:2]      # ['a', 'b']
letters[::2]     # ['a', 'c', 'e']  (step)
letters[::-1]    # reversed
```

## Unpacking

```python
first, *rest = [1, 2, 3, 4]      # first=1, rest=[2,3,4]
a, b = b, a                       # swap
merged = {**dict_a, **dict_b}     # merge dicts
combined = [*list_a, *list_b]     # merge lists
```

## Shallow vs Deep Copy

```python
import copy

original = [[1, 2], [3, 4]]
shallow = original[:]             # or list(original) / copy.copy
deep = copy.deepcopy(original)

original[0][0] = 99
shallow[0][0]                     # 99  (inner list is shared!)
deep[0][0]                        # 1   (fully independent)
```

A shallow copy duplicates the outer container but shares the nested objects. A
deep copy recursively duplicates everything.

## Complexity (Big-O) Cheat Sheet

| Operation | list | dict / set |
| --- | --- | --- |
| Index / key access | O(1) | O(1) avg |
| Membership `in` | O(n) | O(1) avg |
| Append | O(1) amortized | — |
| Insert/remove at front | O(n) | — |

Need fast membership tests? Use a `set` or `dict`, not a `list`.

## Common Mistakes

- Using a `list` for membership checks in a hot loop (O(n) each time).
- Expecting a shallow copy to isolate nested data.
- Mutating a list while iterating over it.

## Interview Questions

- `list` vs `tuple` — differences and when to use each?
- How do you remove duplicates while preserving order?
- Shallow vs deep copy?
- Why can a `tuple` be a dict key but a `list` cannot? (hashability)

## Things to Remember

- `set`/`dict` give O(1) membership; `list` gives O(n).
- Tuples are immutable and hashable → usable as keys.
- `copy.deepcopy` for truly independent nested data.
