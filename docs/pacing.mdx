# Pacing Plan

:::tip[This timeline is flexible]
Fourteen weeks is a guide, not a rule. Go faster where you're comfortable,
slower where you're not. Depth and a working project beat rushing to finish.
:::

## How to Use It

- **Track it** on the [Progress page](/progress) — tick sections as you finish.
- **Build as you go**: from week 7, keep improving the *same* [RAG project](./05-rag-fundamentals/03-first-project.mdx).
- **Don't skip fundamentals**: Python and async underpin everything after.

## If You Have Less Time

- **Already know Python?** Skim weeks 1–2, spend the time on RAG (7–8).
- **Backend experience?** Compress weeks 3–4 and focus on the AI half.
- **Just want RAG?** Do the [Prerequisites](./00-prerequisites/index.mdx), enough [async](./01-python/04-professional-python.mdx#async-python), then weeks 5–8.

## Adjusting the Plan

Life happens. If a week slips, shift the rest — the **order** matters more than
the calendar. The one non-negotiable: finish with a working, evaluated project
you can talk about.

## Done When

- [ ] You've picked a realistic cadence for your situation.
- [ ] You're tracking progress on the [Progress page](/progress).
- [ ] You're building the project continuously, not just reading.
