# Pydantic Validation

:::tip[In this guide]
Pydantic is how FastAPI validates and serializes data. Learn models, field
constraints, validators, nested structures, and the v2 API you'll use today.
:::

## What Is It?

Pydantic turns type-annotated classes into runtime validators and serializers.
FastAPI uses it for request bodies, response models, and settings.

## Why Does It Matter?

Validation at the boundary means the rest of your code can trust its inputs.
Bad data is rejected with a clear `422` before it reaches your logic.

## BaseModel

```python
from pydantic import BaseModel

class Item(BaseModel):
    name: str
    price: float
    in_stock: bool = True        # default => optional in input

item = Item(name="Book", price=9.99)
item.name                         # "Book"
```

Invalid input raises `ValidationError`:

```python
Item(name="Book", price="not-a-number")   # ValidationError
```

## Optional Fields and Defaults

```python
class Profile(BaseModel):
    bio: str | None = None       # optional, defaults to None
    tags: list[str] = []         # default empty list
```

## Field Constraints and Metadata

```python
from pydantic import BaseModel, Field

class CreateUser(BaseModel):
    name: str = Field(min_length=1, max_length=50)
    age: int = Field(ge=0, le=150)
    email: str = Field(pattern=r"^[^@]+@[^@]+\.[^@]+$")
    role: str = Field(default="user", description="user or admin")
```

`Field` adds constraints (`ge`, `le`, `min_length`, `pattern`) and docs that
show up in `/docs`.

## Validators (Pydantic v2)

```python
from pydantic import BaseModel, field_validator, model_validator

class Signup(BaseModel):
    password: str
    password_confirm: str

    @field_validator("password")
    @classmethod
    def strong_enough(cls, v: str) -> str:
        if len(v) < 8:
            raise ValueError("password too short")
        return v

    @model_validator(mode="after")
    def passwords_match(self):
        if self.password != self.password_confirm:
            raise ValueError("passwords do not match")
        return self
```

## Nested Models

```python
class Address(BaseModel):
    city: str
    country: str

class Company(BaseModel):
    name: str
    address: Address                 # nested
    employees: list["Employee"] = []

class Employee(BaseModel):
    name: str
    address: Address | None = None
```

FastAPI validates and documents the full nested shape.

## Serialization (Pydantic v2)

```python
item = Item(name="Book", price=9.99)
item.model_dump()          # {'name': 'Book', 'price': 9.99, 'in_stock': True}
item.model_dump_json()     # '{"name":"Book",...}'
Item.model_validate({"name": "Pen", "price": 1.5})   # parse dict -> model
```

## Pydantic v1 → v2 Cheat Sheet

| v1 | v2 |
| --- | --- |
| `.dict()` | `.model_dump()` |
| `.json()` | `.model_dump_json()` |
| `parse_obj()` | `model_validate()` |
| `@validator` | `@field_validator` |
| `@root_validator` | `@model_validator` |
| `class Config` | `model_config = ConfigDict(...)` |

## Common Mistakes

- Using v1 method names (`.dict()`) on v2 models.
- Putting business logic in validators that belongs in services.
- Forgetting that a field with a default becomes optional in the request.
- Mutable class-level defaults — use `Field(default_factory=list)` for complex defaults.
