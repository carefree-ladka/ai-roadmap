# Testing FastAPI

<TOCInline toc={toc} minHeadingLevel={2} maxHeadingLevel={2} />

:::tip[In this guide]
Testing your API with `TestClient`, swapping real dependencies (DB, auth) for
fakes via overrides, and writing focused integration tests.
:::

## What Is It?

Automated tests that exercise your HTTP endpoints the way a client would, plus
techniques to isolate external systems.

## Why Does It Matter?

APIs are contracts. Tests catch breaking changes to status codes, response
shapes, and auth before your users do.

## TestClient Basics

```python
# tests/test_health.py
from fastapi.testclient import TestClient
from app.main import app

client = TestClient(app)

def test_health():
    resp = client.get("/health")
    assert resp.status_code == 200
    assert resp.json() == {"status": "ok"}
```

`TestClient` runs the app in-process — no server needed.

## Testing POST and Validation

```python
def test_create_item_validates():
    resp = client.post("/items", json={"name": "Book"})  # missing price
    assert resp.status_code == 422

def test_create_item_ok():
    resp = client.post("/items", json={"name": "Book", "price": 9.99})
    assert resp.status_code == 201
    assert resp.json()["name"] == "Book"
```

## Dependency Overrides

Replace real dependencies (DB, external clients) with fakes:

```python
from app.main import app
from app.dependencies import get_db

class FakeDb:
    def get(self, model, id): return {"id": id, "name": "Ada"}

def override_get_db():
    yield FakeDb()

def test_get_user_uses_db():
    app.dependency_overrides[get_db] = override_get_db
    resp = client.get("/users/1")
    assert resp.json()["name"] == "Ada"
    app.dependency_overrides.clear()
```

## Authentication Tests

Override the current-user dependency so you don't need a real login:

```python
from app.security import get_current_user

def fake_user():
    return type("U", (), {"username": "tester", "roles": ["admin"]})()

def test_admin_route_allows_admin():
    app.dependency_overrides[get_current_user] = fake_user
    resp = client.delete("/users/5")
    assert resp.status_code == 200
    app.dependency_overrides.clear()
```

Or test the real flow by logging in and sending the token:

```python
def test_login_and_call():
    token = client.post("/token", data={"username": "ada", "password": "pw"}).json()["access_token"]
    resp = client.get("/me", headers={"Authorization": f"Bearer {token}"})
    assert resp.status_code == 200
```

## Database Tests

Use a disposable database (SQLite in-memory or a throwaway Postgres) with a
fixture that creates and drops schema:

```python
import pytest
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker
from app.models import Base

@pytest.fixture
def db_session():
    engine = create_engine("sqlite:///:memory:")
    Base.metadata.create_all(engine)
    Session = sessionmaker(bind=engine)
    session = Session()
    yield session
    session.close()
```

Then override `get_db` to use `db_session` for the test.

## Integration Tests

Wire real components together (app + real test DB, mocking only the LLM/network)
to verify end-to-end behavior — e.g. `POST /ingest` then `POST /ask` returns a
grounded answer.

## Common Mistakes

- Hitting a real database or network in "unit" tests (slow, flaky).
- Forgetting `app.dependency_overrides.clear()` between tests.
- Asserting only on status code, not the response body.
- Sharing state between tests via a module-level client + real DB.

- `TestClient` runs the app in-process.
- Override dependencies to isolate DB/auth/network.
- Always clear overrides; assert on body + status.
