# Pydantic in FastAPI for AI Development

Pydantic is the data layer of FastAPI. Every request body, query parameter, response, and settings object is validated and serialized by Pydantic. For AI apps, it also does something extra: it gives you **schemas for LLM structured output and tool calling** for free.

This guide starts from the basics and builds toward real AI patterns: chat APIs, structured extraction, tool calling, streaming, RAG, and settings.

> Targets **Pydantic v2** and **FastAPI 0.100+**.

## Why Pydantic for AI APIs

| Need | How Pydantic helps |
| --- | --- |
| Validate user prompts and parameters | Typed request models with constraints |
| Document your API | Automatic OpenAPI and Swagger docs |
| Get reliable JSON from an LLM | `model_json_schema()` and `model_validate_json()` |
| Define tools for agents | JSON Schema generated from a class |
| Manage API keys and config | `pydantic-settings` |
| Keep response shapes stable | `response_model` filters and validates output |

LLMs are probabilistic. Pydantic is the deterministic gate between the model and the rest of your system.

## Pydantic Basics

A model is a class that inherits from `BaseModel`. Annotations become validated fields.

```python
from pydantic import BaseModel

class Prompt(BaseModel):
    text: str
    temperature: float = 0.7      # default value
    max_tokens: int = 512

p = Prompt(text="Hello", temperature="0.2")   # "0.2" is coerced to 0.2
print(p.temperature)        # 0.2
print(p.model_dump())       # {'text': 'Hello', 'temperature': 0.2, 'max_tokens': 512}
```

### Validation errors

```python
from pydantic import ValidationError

try:
    Prompt(text=123, max_tokens="many")
except ValidationError as e:
    print(e.errors())
```

### Optional and nullable fields

```python
class Message(BaseModel):
    role: str
    content: str
    name: str | None = None      # optional, defaults to None
```

### Required vs optional

```python
class A(BaseModel):
    x: int                # required
    y: int | None         # required, but may be None
    z: int | None = None  # optional
```

### Mutable defaults

Pydantic copies defaults safely, but `Field(default_factory=...)` is the clearest option:

```python
from pydantic import BaseModel, Field

class Conversation(BaseModel):
    messages: list[Message] = Field(default_factory=list)
```

### Useful model methods

```python
m = Message(role="user", content="hi")

m.model_dump()                       # dict
m.model_dump(exclude_none=True)      # drop None values
m.model_dump_json()                  # JSON string
Message.model_validate({"role": "user", "content": "hi"})
Message.model_validate_json('{"role":"user","content":"hi"}')
Message.model_json_schema()          # JSON Schema dict
m.model_copy(update={"content": "bye"})
```

## Using Models in FastAPI Requests

Declare a model as a parameter. FastAPI reads the JSON body, validates it, and gives you a typed object.

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class GenerateRequest(BaseModel):
    prompt: str
    temperature: float = 0.7
    max_tokens: int = 256

class GenerateResponse(BaseModel):
    text: str
    tokens_used: int

@app.post("/generate", response_model=GenerateResponse)
async def generate(req: GenerateRequest):
    # call your LLM here
    return GenerateResponse(text=f"Echo: {req.prompt}", tokens_used=5)
```

Invalid input automatically returns **HTTP 422** with details about which field failed.

### Multiple body parameters and `Body`

```python
from fastapi import Body

class User(BaseModel):
    id: int

@app.post("/ask")
async def ask(user: User, req: GenerateRequest, priority: int = Body(1)):
    ...
```

The body is then expected as `{"user": {...}, "req": {...}, "priority": 1}`.

### Embedding a single model

```python
@app.post("/embed-one")
async def embed_one(req: GenerateRequest = Body(embed=True)):
    ...
# expects {"req": {...}}
```

## Field Constraints and Metadata

Use `Field` for constraints, descriptions, and examples. These show up in Swagger **and** in LLM tool schemas.

```python
from pydantic import BaseModel, Field

class ChatParams(BaseModel):
    model: str = Field(default="claude-sonnet-5-5", description="Model identifier")
    temperature: float = Field(0.7, ge=0.0, le=2.0, description="Sampling temperature")
    max_tokens: int = Field(512, gt=0, le=8192)
    top_p: float = Field(1.0, gt=0.0, le=1.0)
    stop: list[str] = Field(default_factory=list, max_length=4)
    user_id: str = Field(..., min_length=3, max_length=64, pattern=r"^[a-zA-Z0-9_-]+$")
```

Common constraints:

| Constraint | Applies to |
| --- | --- |
| `gt`, `ge`, `lt`, `le` | numbers |
| `min_length`, `max_length` | strings, lists |
| `pattern` | strings |
| `multiple_of` | numbers |
| `max_digits`, `decimal_places` | Decimal |

### Annotated style (recommended)

Reusable constrained types:

```python
from typing import Annotated
from pydantic import Field

Temperature = Annotated[float, Field(ge=0, le=2, description="Sampling temperature")]
MaxTokens = Annotated[int, Field(gt=0, le=8192)]

class Params(BaseModel):
    temperature: Temperature = 0.7
    max_tokens: MaxTokens = 512
```

### Examples for Swagger

```python
class GenerateRequest(BaseModel):
    prompt: str = Field(..., examples=["Summarize the French Revolution"])

    model_config = {
        "json_schema_extra": {
            "examples": [
                {"prompt": "Explain transformers in one paragraph", "temperature": 0.3}
            ]
        }
    }
```

### Built-in specialized types

```python
from pydantic import EmailStr, HttpUrl, SecretStr, UUID4, PositiveInt
# EmailStr requires: pip install "pydantic[email]"

class Webhook(BaseModel):
    url: HttpUrl
    secret: SecretStr          # hidden in repr and logs
    owner_email: EmailStr
    request_id: UUID4
    retries: PositiveInt = 3
```

## Response Models

`response_model` validates and **filters** what you return. This protects you from leaking internal fields.

```python
class UserDB(BaseModel):
    id: int
    email: str
    hashed_password: str
    api_key: str

class UserPublic(BaseModel):
    id: int
    email: str

@app.get("/users/{user_id}", response_model=UserPublic)
async def get_user(user_id: int):
    user = UserDB(id=user_id, email="a@b.com", hashed_password="x", api_key="secret")
    return user    # hashed_password and api_key are stripped
```

### Return type annotation (modern style)

```python
@app.get("/users/{user_id}")
async def get_user(user_id: int) -> UserPublic:
    ...
```

### Response control options

```python
@app.get(
    "/items/{id}",
    response_model=Item,
    response_model_exclude_none=True,
    response_model_exclude_unset=True,
    response_model_exclude={"internal_notes"},
)
async def get_item(id: int): ...
```

### Multiple response types

```python
@app.post(
    "/generate",
    response_model=GenerateResponse,
    responses={
        429: {"model": ErrorResponse, "description": "Rate limited"},
        503: {"model": ErrorResponse, "description": "Model unavailable"},
    },
)
async def generate(req: GenerateRequest): ...
```

```python
class ErrorResponse(BaseModel):
    error: str
    code: str
```

### Input and output model separation

A common pattern: `Base`, `Create`, `Update`, `Public`.

```python
class DocumentBase(BaseModel):
    title: str
    content: str

class DocumentCreate(DocumentBase):
    pass

class DocumentUpdate(BaseModel):
    title: str | None = None
    content: str | None = None

class DocumentPublic(DocumentBase):
    id: int
    created_at: datetime
```

For partial updates, use `exclude_unset`:

```python
@app.patch("/documents/{id}", response_model=DocumentPublic)
async def update(id: int, patch: DocumentUpdate):
    data = patch.model_dump(exclude_unset=True)   # only fields the client sent
    ...
```

## Validators

### Field validators

```python
from pydantic import BaseModel, field_validator

class GenerateRequest(BaseModel):
    prompt: str

    @field_validator("prompt")
    @classmethod
    def prompt_not_blank(cls, v: str) -> str:
        v = v.strip()
        if not v:
            raise ValueError("prompt must not be empty")
        return v
```

### Before and after modes

```python
class Query(BaseModel):
    tags: list[str]

    @field_validator("tags", mode="before")
    @classmethod
    def split_csv(cls, v):
        if isinstance(v, str):
            return [t.strip() for t in v.split(",")]
        return v
```

`mode="before"` runs on raw input, `mode="after"` (default) runs after type validation.

### Model validators (cross-field)

```python
from pydantic import model_validator

class RangeRequest(BaseModel):
    start: int
    end: int

    @model_validator(mode="after")
    def check_order(self):
        if self.end <= self.start:
            raise ValueError("end must be greater than start")
        return self
```

### Validate that a prompt fits a token budget

```python
class ChatRequest(BaseModel):
    messages: list[Message]
    max_tokens: int = 512

    @model_validator(mode="after")
    def check_budget(self):
        approx_tokens = sum(len(m.content) for m in self.messages) // 4
        if approx_tokens + self.max_tokens > 128_000:
            raise ValueError("Request exceeds context window")
        return self
```

### Annotated validators (reusable)

```python
from pydantic import AfterValidator

def strip_and_check(v: str) -> str:
    v = v.strip()
    if not v:
        raise ValueError("empty")
    return v

NonBlank = Annotated[str, AfterValidator(strip_and_check)]

class Req(BaseModel):
    prompt: NonBlank
```

## Model Configuration

`ConfigDict` controls model behavior.

```python
from pydantic import ConfigDict

class StrictRequest(BaseModel):
    model_config = ConfigDict(
        extra="forbid",            # reject unknown fields
        str_strip_whitespace=True, # trim strings
        str_min_length=1,
        frozen=True,               # immutable and hashable
        strict=False,              # True disables type coercion
        validate_assignment=True,  # validate on attribute set
        from_attributes=True,      # allow ORM objects
    )
```

| Option | Why it matters for AI APIs |
| --- | --- |
| `extra="forbid"` | Catch typos in parameters and stop LLMs from inventing fields |
| `str_strip_whitespace` | Clean prompts |
| `frozen` | Safe to share config objects |
| `from_attributes` | Convert SQLAlchemy objects to response models |
| `strict` | Avoid surprising coercion like `"1"` to `1` |

### ORM mode

```python
class DocumentOut(BaseModel):
    model_config = ConfigDict(from_attributes=True)
    id: int
    title: str

doc = DocumentOut.model_validate(sqlalchemy_obj)
```

## Discriminated Unions

When a field can be one of several shapes, use a discriminator. This is the right way to model **multimodal message content**, **tool calls**, and **stream events**.

```python
from typing import Annotated, Literal, Union
from pydantic import BaseModel, Field

class TextBlock(BaseModel):
    type: Literal["text"]
    text: str

class ImageBlock(BaseModel):
    type: Literal["image"]
    url: str

class ToolUseBlock(BaseModel):
    type: Literal["tool_use"]
    id: str
    name: str
    input: dict

ContentBlock = Annotated[
    Union[TextBlock, ImageBlock, ToolUseBlock],
    Field(discriminator="type"),
]

class Message(BaseModel):
    role: Literal["user", "assistant"]
    content: str | list[ContentBlock]
```

Benefits: faster validation, precise error messages, and a clean `oneOf` in OpenAPI.

## Building a Chat Completion API

A complete, OpenAI-style chat endpoint using everything so far.

```python title="schemas.py"
from typing import Literal
from pydantic import BaseModel, ConfigDict, Field, computed_field

class ChatMessage(BaseModel):
    role: Literal["system", "user", "assistant"]
    content: str = Field(..., min_length=1)

class ChatRequest(BaseModel):
    model_config = ConfigDict(extra="forbid")

    model: str = "claude-sonnet-5-5"
    messages: list[ChatMessage] = Field(..., min_length=1)
    temperature: float = Field(0.7, ge=0, le=2)
    max_tokens: int = Field(512, gt=0, le=8192)
    stream: bool = False

class Usage(BaseModel):
    prompt_tokens: int
    completion_tokens: int

    @computed_field
    @property
    def total_tokens(self) -> int:
        return self.prompt_tokens + self.completion_tokens

class Choice(BaseModel):
    index: int
    message: ChatMessage
    finish_reason: Literal["stop", "length", "tool_calls"]

class ChatResponse(BaseModel):
    id: str
    model: str
    choices: list[Choice]
    usage: Usage
```

```python title="main.py"
import uuid
from fastapi import FastAPI
from schemas import *

app = FastAPI()

@app.post("/v1/chat/completions", response_model=ChatResponse)
async def chat(req: ChatRequest):
    reply = "Hello! (stub)"
    return ChatResponse(
        id=f"chatcmpl-{uuid.uuid4().hex[:12]}",
        model=req.model,
        choices=[Choice(
            index=0,
            message=ChatMessage(role="assistant", content=reply),
            finish_reason="stop",
        )],
        usage=Usage(prompt_tokens=10, completion_tokens=5),
    )
```

```python
from openai import AsyncOpenAI

client = AsyncOpenAI()

@app.post("/extract/invoice", response_model=Invoice)
```

### Anthropic via forced tool use

Claude returns structured data when you force a tool whose input schema is your model.

```python
import anthropic

client = anthropic.AsyncAnthropic()

async def extract(text: str, schema: type[BaseModel]) -> BaseModel:
    resp = await client.messages.create(
        model="claude-sonnet-5-5",
        max_tokens=1024,
        tools=[{
            "name": "record",
            "description": "Record the extracted data.",
            "input_schema": schema.model_json_schema(),
        }],
        tool_choice={"type": "tool", "name": "record"},
        messages=[{"role": "user", "content": text}],
    )
    tool_block = next(b for b in resp.content if b.type == "tool_use")
    return schema.model_validate(tool_block.input)
```

### Schema tips for better LLM results

- Write `description=` on every field. The model reads it.
- Use `Literal` or `Enum` for categories.
- Prefer flat structures over deeply nested ones.
- Make fields optional (`| None`) when the information may be missing, so the model is not forced to hallucinate.
- Put reasoning fields **before** answer fields to improve accuracy:

```python
class Classification(BaseModel):
    reasoning: str = Field(..., description="Brief step-by-step reasoning")
    label: Literal["spam", "ham"]
    confidence: float = Field(..., ge=0, le=1)
```

## Tool and Function Calling Schemas

Each tool's arguments are a Pydantic model.

```python
from pydantic import BaseModel, Field

class GetWeatherArgs(BaseModel):
    """Get the current weather for a city."""
    city: str = Field(..., description="City name, e.g. Lucknow")
    unit: Literal["celsius", "fahrenheit"] = "celsius"

class SearchDocsArgs(BaseModel):
    """Search the knowledge base."""
    query: str
    top_k: int = Field(5, ge=1, le=20)
```

### Tool registry

```python
from typing import Callable, Awaitable

class Tool:
    def __init__(self, name: str, args_model: type[BaseModel], fn: Callable[..., Awaitable]):
        self.name = name
        self.args_model = args_model
        self.fn = fn

    def spec(self) -> dict:
        schema = self.args_model.model_json_schema()
        return {
            "name": self.name,
            "description": (self.args_model.__doc__ or "").strip(),
            "input_schema": schema,
        }

    async def run(self, raw_args: dict):
        args = self.args_model.model_validate(raw_args)   # validate before executing
        return await self.fn(args)

async def get_weather(args: GetWeatherArgs):
    return {"city": args.city, "temp": 31, "unit": args.unit}

TOOLS = {
    "get_weather": Tool("get_weather", GetWeatherArgs, get_weather),
}
```

### Agent loop with validated tool calls

```python
async def run_agent(user_msg: str):
    messages = [{"role": "user", "content": user_msg}]
    while True:
        resp = await client.messages.create(
            model="claude-sonnet-5-5",
            max_tokens=1024,
            tools=[t.spec() for t in TOOLS.values()],
            messages=messages,
        )
        if resp.stop_reason != "tool_use":
            return "".join(b.text for b in resp.content if b.type == "text")

        messages.append({"role": "assistant", "content": resp.content})
        results = []
        for block in resp.content:
            if block.type != "tool_use":
                continue
            try:
                out = await TOOLS[block.name].run(block.input)
                results.append({"type": "tool_result", "tool_use_id": block.id,
                                "content": json.dumps(out)})
            except ValidationError as e:
                results.append({"type": "tool_result", "tool_use_id": block.id,
                                "is_error": True, "content": e.json()})
        messages.append({"role": "user", "content": results})
```

Sending the `ValidationError` back to the model lets it correct its own arguments.

### Cleaning the schema

Some providers dislike `$defs` or `title` keys. Strip them if needed:


## Validation Retry Loop for LLM Output

LLMs sometimes return invalid JSON or wrong types. Retry with the error message.

```python
import json
from pydantic import ValidationError

async def structured_call(prompt: str, model_cls: type[BaseModel], retries: int = 3):
    messages = [
        {"role": "user",
         "content": f"{prompt}\n\nReturn ONLY JSON matching this schema:\n"
                    f"{json.dumps(model_cls.model_json_schema())}"},
    ]
    for attempt in range(retries):
        resp = await client.messages.create(
            model="claude-sonnet-5-5", max_tokens=1024, messages=messages
        )
        text = resp.content[0].text
        try:
            return model_cls.model_validate_json(extract_json(text))
        except (ValidationError, ValueError) as e:
            messages.append({"role": "assistant", "content": text})
            messages.append({
                "role": "user",
                "content": f"That output was invalid:\n{e}\nFix it and return only JSON.",
            })
    raise RuntimeError("LLM failed to produce valid output")

def extract_json(text: str) -> str:
    start, end = text.find("{"), text.rfind("}")
    return text[start:end + 1]
```

Handling partial or malformed JSON from streams:

```python
from pydantic import BaseModel

partial = Invoice.model_validate_json(chunk, experimental_allow_partial=True)
```

Partial validation is experimental in recent Pydantic v2 releases. Check your installed version's docs before relying on it.

## Streaming Responses (SSE)

Define the event models first.

```python
from typing import Literal, Union, Annotated
from pydantic import BaseModel, Field

class DeltaEvent(BaseModel):
    type: Literal["delta"] = "delta"
    text: str

class DoneEvent(BaseModel):
    type: Literal["done"] = "done"
    usage: Usage

class ErrorEvent(BaseModel):
    type: Literal["error"] = "error"
    message: str

StreamEvent = Annotated[Union[DeltaEvent, DoneEvent, ErrorEvent], Field(discriminator="type")]
```

SSE endpoint:

```python
from fastapi.responses import StreamingResponse

def sse(event: BaseModel) -> str:
    return f"data: {event.model_dump_json()}\n\n"

@app.post("/chat/stream")
async def chat_stream(req: ChatRequest):
    async def gen():
        try:
            async with client.messages.stream(
                model=req.model,
                max_tokens=req.max_tokens,
                messages=[m.model_dump() for m in req.messages if m.role != "system"],
            ) as stream:
                async for text in stream.text_stream:
                    yield sse(DeltaEvent(text=text))
            yield sse(DoneEvent(usage=Usage(prompt_tokens=0, completion_tokens=0)))
        except Exception as e:
            yield sse(ErrorEvent(message=str(e)))

    return StreamingResponse(gen(), media_type="text/event-stream")
```

Client-side parsing with the same models:

```python
from pydantic import TypeAdapter
adapter = TypeAdapter(StreamEvent)
event = adapter.validate_json(line.removeprefix("data: "))
```

## TypeAdapter for Non-Model Types

Validate any type without defining a class. Great for parsing LLM output that is a list or a union.

```python
from pydantic import TypeAdapter

ints = TypeAdapter(list[int])
ints.validate_python(["1", "2", 3])      # [1, 2, 3]

class Entity(BaseModel):
    name: str
    kind: Literal["person", "org", "place"]

entities = TypeAdapter(list[Entity])
result = entities.validate_json(llm_output)

entities.json_schema()                    # schema for a list of Entity
```

Cache `TypeAdapter` instances at module level. Creating one is relatively expensive.

## Background Jobs and Async Task Status

Track long-running AI jobs (batch generation, ingestion, fine-tuning) with a status model.

```python
from enum import Enum
from datetime import datetime, timezone

class JobStatus(str, Enum):
    queued = "queued"
    running = "running"
    succeeded = "succeeded"
    failed = "failed"

class Job(BaseModel):

@app.post("/jobs", response_model=Job, status_code=202)
async def create_job(req: GenerateRequest, tasks: BackgroundTasks):

    JOBS[job.id] = job
    tasks.add_task(run_job, job.id, req)
    return job

@app.get("/jobs/{job_id}", response_model=Job)
async def get_job(job_id: str):
    if job_id not in JOBS:
        raise HTTPException(404, "Job not found")
    return JOBS[job_id]
```

## Performance Tips

- **Reuse models.** Pydantic v2's core is written in Rust, so validation is fast, but building models inside request handlers is wasteful.
- **Use `model_validate_json`** instead of `json.loads` followed by `model_validate`. It parses and validates in one pass.
- **Use `TypeAdapter` at module level**, not per request.
- **Avoid huge embeddings in response models.** Use `Field(exclude=True)` or a separate public model.
- **Use `Annotated` types** to share constraints without subclassing.
- **Prefer `Literal` and discriminated unions** over plain `Union`. Smart-mode union validation tries each member.
- **Use `model_construct`** only for trusted data when you intentionally skip validation.
- For large numeric arrays, consider `numpy` arrays or `bytes` and convert at the boundary.

## Best Practices Checklist

- [ ] Separate **input**, **internal**, and **output** models.
- [ ] Always set `response_model` or a return annotation.
- [ ] Use `extra="forbid"` on request models.
- [ ] Add `description` to every field that an LLM or API consumer will read.
- [ ] Use `Literal`, `Enum`, and discriminated unions instead of free-form strings and dicts.
- [ ] Validate **LLM output** with `model_validate_json`, and retry with the error message.
- [ ] Validate **tool arguments** before executing any tool.
- [ ] Never expose secrets. Use `SecretStr` and exclude sensitive fields.
- [ ] Keep API keys and configuration in `pydantic-settings`.
- [ ] Put upper bounds on `max_tokens`, list lengths, and string sizes to protect cost and memory.
- [ ] Version your schemas (`/v1/...`) when changing response shapes.
- [ ] Test schemas with snapshots, and mock the LLM in endpoint tests.
