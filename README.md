# Local-First AI Engineer Roadmap

A structured, self-paced curriculum that takes you from Python fundamentals all the way to production-grade Retrieval-Augmented Generation (RAG) and agentic AI systems — with an emphasis on running things locally.

The site is built with [Docusaurus](https://docusaurus.io/) and served as a static website. Content lives in `docs/` as Markdown/MDX.

## What's inside

The roadmap is organized as a sequence of modules under `docs/`. Sections
`00`–`14` teach you to build; section `15` prepares you to talk about what you
built.

| Module | Topic |
| --- | --- |
| `00-prerequisites` | Python tooling, core AI concepts, environment setup |
| `01-python` | Python from basics to backend patterns, plus DSA and SQL |
| `02-fastapi` | Building production APIs with FastAPI |
| `03-local-llms-ollama` | Ollama locally, plus NVIDIA NIM, vLLM and GPU sizing |
| `04-embeddings-vector-db` | Embeddings, index internals, pgvector, store operations |
| `05-rag-fundamentals` | Core RAG concepts and pipelines |
| `06-advanced-rag` | The RAG pattern catalog — query transforms through agentic RAG |
| `07-langchain-lcel` | LangChain, LCEL, and LlamaIndex |
| `08-agentic-ai` | Agents, tool design, memory, planning, safety, production |
| `09-mcp` | Model Context Protocol — building and consuming servers |
| `10-production-patterns` | Production concerns and patterns |
| `11-evaluation` | Datasets, metrics, LLM-as-judge, CI gates, online evals |
| `12-fine-tuning` | Whether to fine-tune, then LoRA/QLoRA end to end |
| `13-system-design-interview` | System design and LLD for interviews |
| `14-optional-extensions` | Optional deep-dive directions |
| `15-ai-roadmaps` | Topic-by-topic AI interview roadmaps |

`docs/index.mdx` is the **Start Here** landing page at `/docs`. There's also a
**Progress** tracker and a **Pacing** guide (`docs/pacing.mdx`) to help you plan
how you move through the material.

### Folder conventions

- Folders and files use `NN-kebab-case` prefixes; the number sets sidebar order and is stripped from the URL.
- Each module has an `index.mdx` with `title`, `description`, and a root-relative `slug`, which becomes the module's category link.
- Larger modules group pages into sub-folders (for example `01-python/02-language-deep-dives/`), each with its own `_category_.json`.
- Every page carries frontmatter `title` and `description`; `sidebar_label` is added where the title is too long for the sidebar.
- Cross-document links are relative and include the `.mdx` extension so the build can validate them.

### Site features

- Offline local search (no external service)
- Mermaid diagrams for architecture and system design
- Line numbers on code blocks by default
- Dark mode by default, respecting your system preference

## Prerequisites

- [Node.js](https://nodejs.org/) `>= 20`
- A package manager (`npm`, `yarn`, or `pnpm`)

## Installation

```bash
npm install
```

**Note**: feel free to use the package manager of your choice.

## Local Development

```bash
npm run start
```

This command starts a local development server and opens up a browser window. Most changes are reflected live without having to restart the server.

## Build

```bash
npm run build
```

This command generates static content into the `build` directory and can be served using any static contents hosting service.

To preview the production build locally:

```bash
npm run serve
```

## Type checking

```bash
npm run typecheck
```

## Editing content

- Roadmap content lives in `docs/`, one folder per module.
- The sidebar is autogenerated from the folder structure (`sidebars.ts` + `_category_.json` files), so adding a page is just adding a file with a numeric prefix.
- Section metadata used by the homepage and progress tracker lives in `src/components/roadmap/sections.ts` — update it when you add or rename a module.
- Site configuration (title, navbar, footer, theme) lives in `docusaurus.config.ts`.
- Custom styles are in `src/css/custom.css`.

## Deployment

Using SSH:

```bash
USE_SSH=true npm run deploy
```

Not using SSH:

```bash
GIT_USER=<Your GitHub username> npm run deploy
```

If you are using GitHub Pages for hosting, this command is a convenient way to build the website and push to the `gh-pages` branch.
